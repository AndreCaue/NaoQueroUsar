# Quick Task 261110-u28: Bloquear "JACIRA CHAVARE" no fluxo de extração

One-liner: "JACIRA CHAVARE" (case/accent/whitespace-insensitive, substring) is refused in three layers — paste interception, disabled submit, and a backend 422 that fires before any Groq call.

## What Was Built

### Task 1 — backend helper + unit tests

`backend/app/services/extraction/blocklist.py` is the only place the term and the pt-BR message
live on the backend:

- `BLOCKED_TERM = "JACIRA CHAVARE"`
- `BLOCKED_TERM_ERROR = 'Texto bloqueado — remova "JACIRA CHAVARE" antes de extrair.'`
- `_fold()`: NFKD → strip combining marks → collapse `\s+` → strip → `casefold()`
- `is_blocked_text(text)`: linear `in` comparison of folded strings (no dynamic regex)

`backend/tests/test_blocklist.py` — 14 parametrized cases (no async/fixtures).

Covered variations (all `True`): exact, lowercase, title case, triple spaces, newline,
tab, accent (`CHAVÁRE`), leading/trailing spaces, and a realistic multi-line job blob
with the term mid-text. Negatives (all `False`): empty string, `"JACIRA"`, `"CHAVARE"`,
a normal São Paulo job posting. Plus a message test (`BLOCKED_TERM in BLOCKED_TERM_ERROR`
and `endswith("antes de extrair.")`).

### Task 2 — 422 gate at the endpoint

`backend/app/api/v1/extract.py` imports `BLOCKED_TERM_ERROR, is_blocked_text` and inserts the
guard after the `EXTRACT_MAX_TEXT_BYTES` (413) block and before the `asyncio.timeout` /
`extract_jobs` call:

```python
if is_blocked_text(payload.text):
    raise HTTPException(status_code=422, detail=BLOCKED_TERM_ERROR)
```

Final order: auth dependency → `GROQ_API_KEY` (503) → size (413) → blocklist (422) → `extract_jobs`.
No logging of the pasted text; nothing else in the handler or `extractor.py` changed.

New tests in `backend/tests/test_extract_api.py`:

- `test_extract_422_blocked_term_skips_groq` — monkeypatches `extract_jobs` to append and raise;
  asserts 422, `detail == BLOCKED_TERM_ERROR`, `"JACIRA CHAVARE" in detail`, the unique pasted
  token `segredo-xyz` absent from the response body, and `calls == []`.
- `test_extract_413_wins_over_blocklist` — `EXTRACT_MAX_TEXT_BYTES = 10` with a blocked, oversized
  text returns 413, proving the size gate still has precedence.

### Task 3 — frontend mirror + form wiring

`frontend/lib/blocklist.ts` mirrors the rule exactly (`BLOCKED_TERM`, `BLOCKED_TERM_ERROR`,
internal `fold`, `isBlockedText`), using `[\u0300-\u036f]` because the project targets ES2017.

`frontend/app/admin/paste/ExtractForm.tsx`:

- `type ClipboardEvent` imported from react; `BLOCKED_TERM_ERROR, isBlockedText` from `@/lib/blocklist`.
- New `blockedNotice` state and derived `blocked = blockedNotice || isBlockedText(text)`.
- `handlePaste`: blocked clipboard content → `preventDefault()` + notice; never rewrites existing text.
- `onChange` clears `blockedNotice`; textarea gets `onPaste` and `aria-invalid={blocked || undefined}`.
- Inline `role="alert"` pt-BR notice rendered between the textarea label and the submit button.
- `isSubmitDisabled` now includes `|| blocked`; `handleSubmit` re-checks `isBlockedText(text)` and
  returns before `extractJobs` as the last client-side defence.
- `clearSession` and `handleReset` reset `blockedNotice`.

Login, Turnstile, summary rendering and error rendering untouched. No new dependencies.
