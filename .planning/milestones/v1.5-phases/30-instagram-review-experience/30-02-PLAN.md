## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin browser (EditJobDialog) → backend admin APIs | Admin-entered caption/toggle state sent to backend; client-side checks are UX only, backend remains authority. |
| Backend-prepared IG media URL → img preview in admin dialog | Image URL comes from backend prepare response; render as image src only, no HTML injection. |
| Meta readiness status → UI gating | Readiness state determines if IG controls enabled; unknown/null must fail closed to disabled-visible (D-05). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-P2-01 | Tampering | IG caption/toggle inputs in EditJobDialog | mitigate | Keep client-side 2200/IG-invalid guards for UX, but rely on backend 422 validation on save/generate/approve (Plan 30-01). Display backend error messages safely. |
| T-30-P2-02 | Information Disclosure | IG preview/error rendering | mitigate | Render only returned `image_url` as `<img src>` and validation messages as text; never render caption/media metadata as HTML; no tokens exposed in frontend. |
| T-30-P2-03 | Elevation of Privilege | IG admin API calls from frontend | mitigate | All calls use existing admin Bearer token and handle 401 with existing `handleAuthExpired` redirect; no unauthenticated endpoints used. |
| T-30-P2-04 | Denial of Service | Auto media prepare on open/toggle | mitigate | Guard prepare calls with loading/in-flight state and trigger only on dialog open when IG enabled or on toggle-on (D-06), avoiding repeated concurrent requests. |
