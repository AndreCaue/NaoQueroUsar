# Phase 22 — UI Design Contract

> Visual and interaction contract for frontend hardening/operational changes in this phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Consumes validated Phase 19–21 chat behavior and adds kill-switch-aware UI signaling without regressing the public board.

**Scope boundary (Phase 22 UI):** Operational UI controls only for QA-03 — consult/signal chat disabled state and **hide or disable the chat entry** safely with pt-BR guidance to manual search; preserve all existing public board search/listing, filters, URL behavior, detail dialog, and contact-reveal flows. No new chat capabilities, no semantic search, no history/auth, no new visual primitives, no changes to `JobPublic`/contact exposure, and no Playwright/RTL infrastructure. (Source: 22-CONTEXT.md D-06, D-07, D-04; ROADMAP Phase 22 SC 3–4; REQUIREMENTS QA-03, UI-01..UI-03)

**Inherits:** Phase 21 UI contract (`.planning/phases/21-interface-de-chat-e-integracao-no-board/21-UI-SPEC.md`) and existing public design system in `frontend/app/(public)/public.css`. Only deltas required for kill-switch/disabled-state handling are specified below.

## Spacing Scale

Declared values (multiples of 4), aligned to existing board/chat usage:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tight icon-text gaps, chip vertical padding |
| sm | 8px | Compact gaps within items/chips, small control padding |
| md | 16px | Default element spacing, panel/card inner padding, list gaps |
| lg | 24px | Section/block separation (interpretation vs results vs guidance) |
| xl | 32px | Major internal gaps / desktop breathing room |
| 2xl | 48px | Floating launcher offset from viewport edges |
| 3xl | 64px | Reserved page-level separation (not required inside chat panel) |

Exceptions:
- **44px minimum touch target** for all interactive chat/board controls (launcher when enabled, send/retry/load-more/apply/manual-search, result items, close). (Source: existing `h-11 min-h-11` / `.touch-target` patterns)
- **Safe-area inset** padding where applicable for bottom sheet/dialog contexts (`env(safe-area-inset-bottom)` pattern).
- **No new layout spacing introduced** by Phase 22 when chat is disabled/hidden; board spacing remains unchanged.

## Typography

4 declared sizes, 2 weights (regular 400, semibold 600), consistent with Phase 21/public board:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

**Application notes (prescriptive):**
- **Heading (20px/600):** Panel/section headings (e.g. chat panel title, disabled-notice heading if rendered).
- **Body (16px/400):** Guidance, interpretation, results, error/degraded/disabled explanatory copy.
- **Label (14px/400):** Metadata, helper text, status chips/reasons, secondary actions; short CTA labels may use 600 at 14px for emphasis.
- **Display (28px/600):** Reserved for prominent public board headings outside narrow chat panel; not introduced by Phase 22.
- No new type scale, weights, or font families in this phase.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f0a1a` (`--color-canvas`) | Page background / outer context |
| Secondary (30%) | `#1a1025` (`--color-surface`) | Panel/sheet/card/input surfaces |
| Accent (10%) | `#8b5cf6` / `#a78bfa` / `#7c3aed` (existing accent tokens) | **Reserved for enabled chat affordances:** launcher (enabled), focus-visible ring, primary apply CTA, actionable emphasis (load more/retry as defined), applied-status emphasis, interactive hover/focus borders |
| Destructive | `#f87171` (`--color-danger`) | Error-state text/icon emphasis only (no destructive user actions in this phase) |

Accent reserved for (explicit list — never "all interactive elements"):
1. Focus-visible ring on interactive elements (`--color-accent-soft`)
2. Enabled floating chat launcher affordance/border/hover highlight
3. Primary "Aplicar no board" CTA (filled `--color-accent-strong`, white text, hover `--color-accent-strong-hover`) when applicable
4. Actionable emphasis for "Carregar mais vagas" / "Tentar novamente" per existing contract
5. "Aplicado" status indicator
6. Active/hover border on clickable result items

**Phase 22 delta:** When chat is **disabled by kill-switch/config**, the chat entry is not presented as an enabled accent affordance (see Component/Interaction contract). No new colors or semantic tokens are introduced.

## Component & Interaction Contract (Phase 22 Deltas)

| Component / Area | Prescriptive behavior | Source |
|------------------|-----------------------|--------|
| `ChatWidget` / `ChatLauncher` (existing, `frontend/components/board/chat/*`) | **Disabled state (kill-switch/config):** hide the chat launcher/entry and do not render/open the chat panel. Board layout, toolbar, filters, list, pagination, detail/reveal, and manual search remain fully usable and visually unchanged. No dead/disabled floating control is shown. | D-06, ROADMAP SC 4 |
| Disabled-state signaling mechanism | Frontend must consult a backend-provided operational signal (exact transport/shape per implementation discretion, e.g. config flag/endpoint/response state) and treat "chat disabled" as a safe non-interactive state. Signal handling must fail safe for UX (do not expose internal errors) and must not block board rendering. | D-06, D-07 |
| `POST /api/v1/public/chat-search` boundary (UI-observable) | If invoked while disabled, backend returns a **safe, controlled** pt-BR disabled response/guidance (no internal details). UI must not assume success; if a disabled/guidance response is encountered, show guidance and route user to manual search (no automatic results, no apply action). | D-06, CONTEXT D-08/D-11 intent |
| Manual search continuity | Manual board search (`q/city/sort/page`, toolbar, grid, pagination, `JobDetailDialog`/`RevealContact`) must behave identically whether chat is enabled, degraded, or disabled. | D-06, ROADMAP SC 4, QA-03 |
| Privacy/observability (UI boundary) | No user message content, contact data, or PII is added to client-visible telemetry/log UI surfaces in this phase. Chat payload/UI continues to expose no contacts. | D-07, D-16 (Phase 21), PROJECT core value |

**Note:** Phase 22 does not alter Phase 21 interpretation/result/apply/detail flows except to respect disabled state and preserve manual-search fallback. Existing degraded/error/empty/loading states and copy remain valid per Phase 21 contract.

## Copywriting Contract

All user-facing copy in pt-BR. Safe, non-technical, no internal details, no PII. (Source: 22-CONTEXT D-06, D-35; Phase 21 guidance patterns)

| Element | Copy |
|---------|------|
| Primary CTA (when chat enabled and applicable) | `Aplicar no board` (unchanged from Phase 21) |
| Manual search shortcut (fallback, unchanged) | `Usar busca manual` |
| Chat disabled notice heading | `Busca por chat indisponível` |
| Chat disabled notice body | `A busca por chat está indisponível no momento. Use a busca manual para encontrar vagas.` |
| Chat disabled guidance (inline/response-consumed) | `Use a busca manual para encontrar vagas.` (short actionable guidance; compatible with backend-provided pt-BR guidance, no internal details) |
| Empty state heading | `Encontre vagas conversando` (unchanged; only shown when chat enabled and panel empty) |
| Empty state body | `Diga o cargo, cidade ou formato que você procura. Toque em um exemplo para começar.` (unchanged) |
| Error state | `Não foi possível buscar agora.` with action `Tentar novamente` and fallback `Usar busca manual` (unchanged) |
| Destructive confirmation | Not applicable — no destructive actions in this phase. |

**Prescriptive rules:**
- When chat is disabled, do **not** claim partial availability; present the disabled notice/guidance above only if a chat surface is rendered in that state (preferred behavior is hidden launcher/panel). Never expose internal reason codes, stack traces, provider names, or configuration details.
- Keep all existing Phase 21 copy for enabled/degraded/partial/empty-result states intact unless strictly required to reflect disabled/manual fallback; any adjustment must remain pt-BR, safe, and consistent with `JobPublic`/no-contact constraints.
