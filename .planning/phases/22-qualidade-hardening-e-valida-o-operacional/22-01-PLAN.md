<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public client -> `POST /api/v1/public/chat-search` | Untrusted anonymous input and abuse/cost surface; must not expose contacts/PII/internals |
| Public client -> `GET /api/v1/public/chat-search/status` | Public operational signal; must reveal only enabled/disabled state, no secrets |
| Backend app -> logs/telemetry sink | Operational events must exclude user message, extracted free text, contacts, and other PII |
| Chat subsystem -> public board (`GET /public/jobs`, UI manual flows) | Availability coupling must not regress manual search/list/detail/reveal |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | Information Disclosure | `backend/app/api/v1/public.py` logging, responses | mitigate | Emit only `outcome/reason/latency_ms/results_count/total/page/limit` in `logger.info("chat_search", extra={...})`; never log `payload.message`/contacts; disabled/degraded responses return `JobPublic` empty items and safe pt-BR guidance without traceback/provider/internal strings |
| T-22-02 | Denial of Service | `backend/app/api/v1/public.py` chat endpoint, config kill-switch | mitigate | Honor `CHAT_SEARCH_ENABLED` as cheap short-circuit before `extract_and_map_intent`/`list_published`; keep existing rate limit `@limiter.limit(chat_search_limit)` and bounded request schema/timeout behavior intact |
| T-22-03 | Tampering / Spoofing of state | `GET /api/v1/public/chat-search/status`, disabled handling | mitigate | Status endpoint exposes only boolean enabled state from server settings; backend remains authoritative by enforcing controlled `chat_disabled` response even if client state is stale/misused |
| T-22-04 | Elevation of Privilege / Data exposure | Public payload contract | mitigate | Preserve `ChatSearchResponse`/`ChatSearchResults.items: list[JobPublic]` (no contacts) and keep `GET /public/jobs` and other public routes independent of chat toggle |
</threat_model>
