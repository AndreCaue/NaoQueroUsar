<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin browser UI → backend integrations API | Authenticated client calls carry Bearer token and user actions (connect/verify/select/disconnect) that change integration state |
| Browser redirect/callback return → Integrações page | Untrusted query params (`result`, `pending`, `reason`) influence banners/flow hints and must be treated as untrusted display inputs |
| Frontend runtime/storage → network/devtools | Client-side code must not persist or expose Meta tokens/secrets in storage, URLs, or rendered UI |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-13 | Information Disclosure | `frontend/lib/api.ts`, `IntegrationsClient.tsx`, callback banner rendering | mitigate | Use only safe backend payloads and whitelisted result codes for UI; never read/render/store access tokens, app secret, or OAuth code; avoid echoing raw backend/provider errors (META-05, D-03, D-11, D-16). |
| T-15-14 | Elevation of Privilege | Admin-only actions in UI (verify/select/disconnect/start) | mitigate | Gate page with `useAdminGuard()` and send Bearer token from `sessionStorage` on all sensitive API calls; rely on backend `require_admin` for enforcement (D-04, D-13). |
| T-15-15 | Tampering | Callback/query-param driven UI state and pending selection | mitigate | Treat `result/pending/reason` as hints only; always refresh authoritative status/pending data from authenticated backend endpoints before confirming actions; enable `Confirmar página` only for explicitly selected backend-listed page (D-05, D-08, D-16). |
| T-15-16 | Spoofing / CSRF-adjacent UX | Connect/reconnect initiation flow | mitigate | Start OAuth via authenticated backend start endpoint that returns server-built dialog URL, then same-tab navigate; never construct token exchange params client-side and never attach secrets to Meta URL (D-02, D-04, META-02). |
| T-15-17 | Denial of Service (operational UX) | Verify/connect/disconnect action handling | mitigate | Implement loading/disabled in-flight states, ApiError handling, and transient-verify-safe messaging that preserves valid connection display to prevent misleading operator actions (D-10, D-14). |
| T-15-18 | Repudiation (user action safety) | Disconnect action | mitigate | Require explicit confirmation dialog with destructive confirm/cancel labels before calling disconnect API (D-07, D-15). |
</threat_model>
