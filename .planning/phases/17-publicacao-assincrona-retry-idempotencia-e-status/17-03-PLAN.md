<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin UI -> backend admin APIs | Chamadas autenticadas por Bearer; UI deve tratar 401/erros sem vazar dados sensíveis |
| Backend payloads -> renderização admin | Apenas dados seguros podem ser exibidos; erros em pt-BR resumidos |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-11 | Information Disclosure | `lib/api.ts`, componentes admin sociais | mitigate | Renderizar somente campos seguros do contrato (`status_label`, `last_error`, `published_url`, `external_post_id`, timestamps); nunca exibir tokens/segredos/payload bruto/stack trace; mensagens de erro fallback em pt-BR. |
| T-17-12 | Tampering / Integrity (UI double-submit) | botões `Tentar novamente` (dialog/lista/row se aplicável) | mitigate | Single-flight por item (state/ref) com disable + `Tentando novamente...` durante request, dedupe de cliques, refetch/atualização por resposta idempotente do backend; não habilitar para inelegíveis (D-12,D-15). |
| T-17-13 | Elevation of Privilege (sessão expirada) | chamadas admin em novas telas/componentes | mitigate | Reutilizar padrão de 401: limpar `nqu_admin_token` e redirecionar para `/admin/paste` quando `ApiError.status === 401`. |
| T-17-14 | Spoofing / Confusão de usuário | ações inelegíveis/reconexão | mitigate | Exibir orientações pt-BR conforme UI-SPEC (reconectar -> `Abrir Integrações`, aguardando agendamento, em andamento, publicado) e não sugerir edição/remoção de post no Facebook. |
</threat_model>
