<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Cron externo -> endpoint worker | Acionamento operacional do worker sem sessão admin |
| Admin UI/client -> endpoints de status/retry | Leitura e mutação de estado de publicação restritas ao admin |
| Backend -> UI/admin payloads | Respostas devem expor apenas dados seguros (sem tokens/segredos/payload bruto) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-06 | Spoofing / Elevation of Privilege | `POST /admin/social/worker` | mitigate | Proteger com `Depends(require_cron_secret)` reutilizando `CRON_SECRET`/`X-Cron-Secret` (mesmo padrão de `/admin/expire`, D-02); não aceitar Bearer admin como substituto. |
| T-17-07 | Elevation of Privilege / Information Disclosure | endpoints status/list/retry | mitigate | Exigir `Depends(require_admin)` em todas as rotas de status/lista/retry; retornar apenas campos seguros (status/labels, erro resumido pt-BR, link/id público, timestamps/eligibilidade) sem tokens, sem texto sensível desnecessário. |
| T-17-08 | Tampering / Integrity (duplicidade/replay) | retry manual e dispatch imediato | mitigate | Retry e dispatch imediato sempre delegam ao `run_social_publish_cycle/process_social_post_safe` (claim+idempotência D-03/D-09..D-12); rejeitar/retornar no-op idempotente para publicado, em processamento/publicação já resolvida ou não elegível. |
| T-17-09 | Denial of Service | worker/retry endpoints | mitigate | Worker processa apenas lote limitado de elegíveis devidos; retry atua por alvo específico (job/post) e respeita elegibilidade; erros tratados sem travar aprovação do site (PUB-02). |
| T-17-10 | Tampering (regressão de fluxo) | `approve` site-first | mitigate | Manter `approve_job + commit + refresh` antes de qualquer dispatch social; agendar background apenas após commit e capturar falhas de dispatch sem alterar resposta de sucesso da vaga. |
</threat_model>
