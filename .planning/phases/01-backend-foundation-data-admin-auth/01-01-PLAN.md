<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | Untrusted HTTP (method, path, headers, body) enters FastAPI |
| API→Neon | SQLAlchemy issues SQL over TLS to Postgres |
| environment→process | Secrets loaded from env; must never be logged or committed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information disclosure | secrets in logs/repo | mitigate | `.env` gitignored; `.env.example` placeholders only; `configure_logging` never logs settings; `extra="ignore"` prevents accidental leakage into models |
| T-01-02 | Denial of service | CORS wildcard / oversized origins | mitigate | CORS restricted to `settings.cors_origins_list`; `allow_credentials=False` |
| T-01-03 | Tampering | startup with misconfigured env | mitigate | `pydantic-settings` required fields fail fast (no silent defaults for secrets) |
| T-01-04 | Denial of service | Neon CU-hour burn from keep-alive | mitigate | `pool_pre_ping=True` + small default pool; `/health` is liveness-only (no DB ping) so monitoring does not wake compute; dispose engine on shutdown (PITFALLS 12) |
| T-01-05 | Spoofing | TLS/identity to DB | transfer | Neon enforces `ssl=require` on the pooled endpoint (platform-managed) |
</threat_model>
