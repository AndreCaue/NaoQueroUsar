<objective>
Deliver the master-admin authentication contract: bcrypt/argon2 password verification against `ADMIN_PASSWORD_HASH`, JWT issuance on `POST /api/v1/auth/login`, and a `require_admin` dependency that rejects any request without a valid `Authorization: Bearer <token>` — exercised by a protected `GET /api/v1/admin/me`.

Purpose: Criteria 1 and 2, and requirements ADMN-01 (env password login), ADMN-02 (JWT session), ADMN-03 (admin routes block unauthenticated). Phase 3 (SECR-03) will add Turnstile + rate limiting to this same login endpoint (D-04) — the endpoint is built here without those, and the phase boundary is respected.

Output: A working login endpoint and the guard dependency every future admin route (Phases 2/5/6) will reuse.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API (login) | Untrusted password + credentials crossing into auth logic |
| client→admin routes | Untrusted Bearer token/claims must be validated every request |
| app→env | Password hash + JWT secret read from environment |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | `/auth/login` brute force / credential stuffing | accept (deferred) | Phase 1 verifies only the hash; rate limiting + Turnstile intentionally deferred to Phase 3 per D-04/SECR-03 |
| T-03-02 | Spoofing | forged JWT (algorithm confusion / weak secret) | mitigate | HS256 with `JWT_SECRET`; decode pins `algorithms=["HS256"]` to prevent alg confusion |
| T-03-03 | Elevation of privilege | access admin route without valid token | mitigate | `require_admin` dependency on every admin route; missing/invalid/expired -> 401; claims sub/role checked |
| T-03-04 | Information disclosure | password/token/secret leakage | mitigate | bcrypt hash stored in env (D-03); secrets never logged; 401 responses carry no token |
| T-03-05 | Repudiation | no record of auth failures | accept | Structured logging covers requests; audit log deferred (MVP, PITFALLS "No audit log" acceptable) |
| T-03-06 | Repudiation | long-lived stolen token | mitigate | 12h expiry (D-02) bounds replay window; no refresh token by design |
</threat_model>
