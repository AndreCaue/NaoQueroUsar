## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, label-to-input gap (`0.25rem` in existing CSS) |
| sm | 8px | Compact element spacing, input padding (`0.5rem`) |
| md | 16px | Default element spacing, button padding, alert/error panel margins |
| lg | 24px | Panel padding on mobile, form section separation |
| xl | 32px | Layout gaps (admin panel rhythm) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (`2rem` page padding on desktop per `.admin-page`) |

Exceptions:
- **Turnstile widget footprint:** Cloudflare renders a fixed ~300×65px box (or checkbox variant) — not a spacing token; reserve `300px` min width and let it flow naturally. Never transform/scale it.
- **Touch targets:** min-height **44px** for all buttons (admin login "Entrar", reveal "Mostrar contato") — mobile-first requirement overrides the 8-point scale only for interactive min-heights.

|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 400 (regular) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |

Rules:
- Exactly **2 weights**: 400 and 600. No bold (700), no light.
- Error/alert copy: **Body role at 400** (never italic, never smaller than 14px).
- Contact values after reveal (email/phone): Body role, weight **600**, color `--accent-soft` (`#a78bfa` — WCAG AA on `#0f0a1a`/`#1a1025`).
- Status/counter text (e.g. "Entrando...", "Verificando..."): Label role (14px/400/1.4).

## Interaction Contract

### A. Admin login (built in this phase — `ExtractForm.tsx`, already `"use client"`)

**Focal point:** the "Entrar" primary CTA is the visual anchor (accent bg on the `#1a1025` panel); the Turnstile widget is secondary (neutral, Cloudflare-rendered). In the Phase 4 reveal modal, the revealed contact block is the payoff focal point (`--accent-soft` `#a78bfa`, weight 600).

1. Render `<Turnstile siteKey={NEXT_PUBLIC_TURNSTILE_SITE_KEY} action="login" theme="dark" onVerify onExpire />` **above** the "Entrar" button, inside the login block.
2. "Entrar" disabled while: `loading || !password.trim() || !cfToken`.
3. `onVerify(token)` → store token; `onExpire()` / `onError()` → `setCfToken(null)` (stale token must never be submitted).
4. On failed login (401/403/429): show error panel + **reset the widget** (`turnstile.reset` via `next-turnstile` ref/props) so a consumed token isn't reused.
5. `lib/api.ts`: `loginAdmin(password, cfToken)` sends `{ password, cf_token }` — signature change and widget ship in the **same plan** (anti-pattern: changing `/auth/login` shape without the frontend → 422).
6. Import `<Turnstile>` only in `"use client"` files (package has no `"use client"` directive — verified in 03-RESEARCH).

### B. Reveal flow (Phase 4 implements; contract fixed here)

State machine: `idle → verifying → revealed | error(403|429|404|network)`.

| State | Visual |
|-------|--------|
| idle | Accent button "Mostrar contato" (44px min-height); contact fields **absent from DOM** (never hidden-but-present) |
| verifying | Button disabled, label "Verificando...", Turnstile widget mounted/executing at reveal time (tokens live 300s — do NOT pre-mint) |
| revealed | Contact block replaces button: `wa.me` link (accent, weight 600) + email mailto link (accent); copy contract above applies on failures |
| error(403) | Error panel with backend detail; **reset widget**, keep user in modal |
| error(429) | Error panel; disable reveal button for `Retry-After` seconds (if header absent, 10s) |
| error(404) | Error panel "Vaga não encontrada ou expirada." |

Rules:
- Never render contact values from the list/detail payload (PUBL-05 — contact exists only in `ContactRevealResponse`).
- Never cache a "verified" flag client-side across modal open/close — a new reveal = a new token.
- Submit only when `cf_token` present; treat 403 as retryable (user problem), not a bug.

### C. Universal

- Focus ring `2px solid #a78bfa` / offset 2px on all interactive elements.
- Disabled: `opacity: .5; cursor: not-allowed` (existing pattern).
- Buttons: min-height 44px, text weight 600.
- All screens mobile-first; admin login single-column (`max-width: 720px` panel already exists).
