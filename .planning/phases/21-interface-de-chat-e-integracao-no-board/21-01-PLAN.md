<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> public chat-search API | User-controlled NL message and untrusted JSON response cross client/server boundary |
| chat response render -> DOM | Server-provided interpretation/guidance/limitations and job fields rendered in UI (must not become HTML/script) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-01 | Tampering | `frontend/lib/api.ts` chatSearch request/response handling | mitigate | Send JSON with explicit Content-Type, enforce finite timeout, treat non-2xx/transport as typed errors, never trust response shape beyond typed parsing points; do not bypass server validation. |
| T-21-02 | Information Disclosure | chat client types/state foundations | mitigate | Define chat result types around `JobPublic` only and exclude all `contact_*` fields from chat contracts/helpers so contacts cannot enter chat state/render paths. |
| T-21-03 | Tampering | `frontend/lib/chatApply.ts` URL mapping | mitigate | Route all apply mapping through `normalizeFilters`/whitelisted slugs/sort and force `page:1`, `vaga:null`; omit null params to avoid injecting unsupported or stale filters. |
</threat_model>
