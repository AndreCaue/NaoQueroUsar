<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input -> chat-search API | Untrusted pt-BR message sent from browser to public endpoint |
| chat-search API response -> UI state/render | Untrusted interpretation/guidance/results rendered and used to drive board navigation |
| chat results -> canonical detail/reveal flow | Public `JobPublic` items cross into existing detail dialog; contact reveal remains protected in detail only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-04 | Information Disclosure | `ChatWidget`/results rendering | mitigate | Render only `JobPublic` public fields (título/empresa/local/salário quando disponível), never include contact fields/state, and reuse `JobDetailDialog`/`RevealContact` as the exclusive reveal path. |
| T-21-05 | Tampering | interpretation/results UI rendering | mitigate | Render all user/API strings as text nodes (no `dangerouslySetInnerHTML`), show server-authoritative statuses/limitations/guidance without inventing support, and keep apply gated by `canApplyChatToBoard`. |
| T-21-06 | Denial of Service | send/load-more interaction flow | mitigate | Disable duplicate sends and in-flight load-more actions, scope pagination to active query/message, handle timeout/network errors with retryable pt-BR states, and avoid request storms from rapid clicks. |
| T-21-07 | Elevation of Privilege (workflow bypass) / Tampering | apply-to-board and detail layering | mitigate | Apply only whitelisted canonical params via `appliedParamsToBoardFilters`+`buildBoardHref` with `page=1`/`vaga` cleared, and enforce chat/detail layering rules so reveal/detail remains in canonical controlled flow. |
</threat_model>
