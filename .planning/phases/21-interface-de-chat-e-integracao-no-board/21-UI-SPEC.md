# Phase 21 — UI Design Contract

> Visual and interaction contract for the public board chat UI. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Consumes `POST /api/v1/public/chat-search` (Phase 20) and integrates with canonical board URL/detail/contact flows. No contacts are ever exposed in chat payload or UI.

**Scope boundary:** UI integration only (chat access, interpretation/results rendering, apply-to-board, open canonical detail). No backend contract changes, no semantic search, no persistent history/auth, no full QA/E2E/ops suite (Phase 22). (Source: 21-CONTEXT.md §domain, REQUIREMENTS UI-01..UI-03)

## Spacing Scale

Declared values (multiples of 4), aligned to Tailwind spacing used in board (`gap-1/2/3/4/6`, `p-2/3/4`, `px-2/py-0.5` for chips):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Chip/label inline padding (vertical), tight icon-text gaps |
| sm | 8px | Compact gaps within items/chips, small control padding |
| md | 16px | Default element spacing, card/panel inner padding, list item gaps |
| lg | 24px | Section/block separation inside panel (interpretation vs results vs guidance) |
| xl | 32px | Panel header/footer breathing room on desktop, major internal gaps |
| 2xl | 48px | Floating launcher offset from viewport edges / safe separation from board chrome |
| 3xl | 64px | Reserved page-level separation (not required inside panel; avoid over-spacing in narrow sheet) |

Exceptions:
- **44px minimum touch target** for launcher, send, retry, "Carregar mais", "Aplicar no board", result items, and example chips (accessibility/touch; existing `.touch-target`/`h-11 min-h-11` pattern). (Source: JobCard/BoardToolbar patterns, CONTEXT UI-01 mobile-first)
- **Chip pill padding** may use 4px/8px combinations (e.g. `px-2 py-1` equivalents) for compact status labels while preserving 44px tap area on interactive chips.
- **Safe-area inset** padding-bottom on mobile sheet/dialog contexts as applicable (`env(safe-area-inset-bottom)` pattern exists for dialogs).

## Typography

4 declared sizes, 2 weights (regular 400, semibold 600) — consistent with existing board usage (`text-sm/base/xl`, `font-medium/semibold` mapped to contract weights):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.5 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

**Application notes (prescriptive):**
- **Display (28px/600):** Not used inside the narrow chat panel; reserved only if a prominent empty-state hero is needed in desktop drawer (prefer Heading). Default: omit in-panel to preserve density.
- **Heading (20px/600):** Panel title ("Buscar vagas no chat" or equivalent) and empty-state heading.
- **Body (16px/400):** Message text, interpretation summary ("Entendi…"), result primary details, guidance/error body, limitations text.
- **Label (14px/400):** Metadata, status chips/reasons, field labels, helper/placeholder-adjacent text, result secondary info (empresa/local/salário line labels when needed), timestamps/counts; use `font-semibold` (600) only for short emphasis labels (e.g. chip value, CTA labels) while keeping size 14px.
- Use `text-fg` for primary content, `text-fg-muted` for secondary/meta, `text-accent-soft` for inline emphasis links/actions consistent with board. Long text wraps with `[overflow-wrap:anywhere]` where needed.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f0a1a` (`--color-canvas`) | Page background behind panel; outer viewport context |
| Secondary (30%) | `#1a1025` (`--color-surface`) | Chat panel/sheet/drawer surface, result items/cards, input field surface areas |
| Accent (10%) | `#8b5cf6` / `#a78bfa` / `#7c3aed` (existing accent tokens) | **Reserved for:** floating launcher affordance/border-highlight, panel focus/active states, primary actionable chat controls (send/apply/load-more emphasis where primary), selected/interactive hover borders, focus ring (`--color-accent-soft`), status emphasis that indicates "aplicado" (accent-toned chip/badge) |
| Destructive | `#f87171` (`--color-danger`) | Error state text/icon accents and retry emphasis **only** (no destructive user actions in this phase) |

Accent reserved for (explicit list — never "all interactive elements"):
1. Floating chat launcher button (icon/border/hover/focus highlight)
2. Focus-visible ring on interactive elements (`--color-accent-soft`)
3. Primary "Aplicar no board" CTA (filled `--color-accent-strong` with white text, hover `--color-accent-strong-hover`) when action is applicable
4. "Carregar mais" and "Tentar novamente" actionable emphasis (border/text accent) — not filled-destructive except error context
5. "Aplicado" status chip/badge indicator
6. Active/hover border on clickable result items (consistent with `job-card` hover/focus-within accent border)

**Non-accent interactive/structural elements:** secondary buttons, neutral chips ("ignorado"), borders (`--color-line`, `--color-line-strong`), muted labels (`--color-fg-muted`), and plain text remain non-accent. "Aproximado" status uses a distinct non-accent warning/neutral treatment (e.g. muted text + bordered chip) with reason text — no new semantic color token required beyond existing palette; do not imply guaranteed filtering.

## Copywriting Contract

All user-facing copy in pt-BR. Reflect API/server-authoritative interpretation faithfully; never invent supported filters or expose contacts. (Source: CONTEXT D-03..D-08,D-12,D-16, STATE v1.3 decisions, backend guidance patterns)

| Element | Copy |
|---------|------|
| Launcher (accessible label) | `Abrir busca por chat` |
| Panel title | `Buscar vagas no chat` |
| Close/minimize control label | `Fechar chat` |
| Message input placeholder | `Descreva a vaga que você procura (ex.: cargo, cidade, remoto)...` |
| Send CTA | `Enviar mensagem` |
| Primary CTA (apply to board) | `Aplicar no board` |
| Primary CTA helper (when approximations/limits apply) | `Alguns critérios podem ser aproximados ou não filtrados.` (short note shown adjacent to CTA; keep interpretation block as source of detail) |
| Load more CTA | `Carregar mais vagas` |
| Result item affordance | `Ver detalhes` (visible label/hint on each clickable result item; entire item clickable per D-15) |
| Manual search shortcut | `Usar busca manual` (navigates/focuses board filters/search context; shown in empty/degraded/error guidance states) |
| Empty state heading | `Encontre vagas conversando` |
| Empty state body | `Diga o cargo, cidade ou formato que você procura. Toque em um exemplo para começar.` |
| Suggested examples (2–4 clickable, D-03) | `Dev pleno em São Paulo`; `Frontend React remoto`; `Estágio em marketing digital em SP`; `Analista de dados em BH ou remoto` |
| Loading state (thread indicator) | `Interpretando sua busca...` (visible indicator; block duplicate sends until complete) |
| Interpretation summary prefix | `Entendi: {resumo em linguagem natural}` (derived from response; show "Entendi…" even when partial) |
| Field status labels (chips/rows) | `Aplicado` · `Ignorado` · `Aproximado` (each with reason from `field_statuses.reason`; show understood vs applied values when available) |
| Limitations/guidance block title | `Limites desta busca` (separate, legible block for `limitations` and `meta.guidance`) |
| Empty results state (after successful interpretation, no items) | **Heading:** `Nenhuma vaga encontrada`  **Body:** `Não encontramos vagas com o que foi aplicado. Ajuste sua mensagem ou use a busca manual.` |
| Error state (request failure/timeout/network) | **Message:** `Não foi possível buscar agora.`  **Action:** `Tentar novamente` (plus `Usar busca manual` shortcut) |
| Degraded/fallback state (LLM unavailable/timeout/no extractable params, per API) | Show API `meta.guidance`/`limitations` prominently; **explicit notice:** `Não houve resultados automáticos.` with `Usar busca manual` shortcut; do not present "Aplicar no board" as primary when no useful/applicable params |
| Partial support note (non-native fields) | Never claim guaranteed filtering for salário/modalidade/contrato/senioridade; surface as `Aproximado`/limitation per contract (e.g. reason-guided text) |
| Destructive confirmation | Not applicable — no destructive actions in chat UI for this phase. |

**State/behavior copy rules (prescriptive):**
- Send control disabled while request in flight (D-04); retry reuses/edits draft without duplicating in-flight requests.
- When "Aplicar no board" is unavailable (degraded or no applicable/useful params per D-11), hide or disable primary apply action and prioritize guidance + `Usar busca manual`.
- Result items display only: título, empresa (when available), local, salário (when available) — never contact fields (D-06, D-16).

## Interaction & State Contract

| Scenario | Required UI behavior | Source |
|----------|----------------------|--------|
| Open chat | Launcher opens responsive panel (bottom sheet mobile / drawer-modal desktop); board remains primary context | D-01 |
| Close/reopen without reload | Panel hides/shows; conversation, interpretation, results, and composer state preserved in memory | D-02, D-10, D-14 |
| Page reload | Chat state resets to empty initial state | D-02 |
| Initial empty state | Placeholder/instruction + 2–4 clickable example queries | D-03 |
| Send | Visible "Interpretando sua busca..." indicator in thread; disable duplicate sends; on success render interpretation + results/guidance per contract | D-04, D-05, D-08 |
| Send failure | Clear pt-BR error "Não foi possível buscar agora." with "Tentar novamente" and manual-search shortcut | D-04, D-08 |
| Results pagination | Show first page; "Carregar mais vagas" fetches next page for same active message/query and appends items; disable when loading or no more (`items.length >= total`) | D-07 |
| Degraded/no automatic results | Highlight `limitations`/`meta.guidance`, show "Não houve resultados automáticos.", offer `Usar busca manual`; suppress primary apply when no useful params | D-08, D-11 |
| Apply to board | If applicable params exist, replace `q/city/sort` with effective `applied_params`, clear `vaga`, reset `page=1`; navigate via canonical href/replace; close/minimize chat; show partial-support note when approximations/limits present | D-09, D-10, D-11, D-12 |
| Open detail from chat | Clicking a result (entire item) closes/minimizes chat and opens canonical `?vaga=<id>` / `JobDetailDialog` with `JobPublic` item; on detail close return to board and allow reopening chat with preserved state | D-13, D-14, D-15 |
| Contact reveal | Never in chat; only via existing `RevealContact` inside detail flow | D-16, PROJECT core value |
