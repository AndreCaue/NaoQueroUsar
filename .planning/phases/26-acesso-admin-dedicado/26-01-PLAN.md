<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser URL/query -> client router | `next` query param is untrusted input; must be sanitized before navigation |
| Browser sessionStorage -> admin guard | Token presence gates client UI only; backend remains auth authority |
| Client -> POST /api/v1/auth/login | Password + Turnstile token cross trust boundary; backend validates rate limit, Turnstile, password |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-01 | Spoofing | `frontend/lib/adminReturnTo.ts` | mitigate | `sanitizeAdminReturnTo` accepts only paths starting with `/admin`, rejects `//`, `\`, absolute URLs, and maps `/admin/login*` to `/admin`; covered by `adminReturnTo.test.ts` (Task 1) |
| T-26-02 | Elevation of Privilege | `AdminGuard.tsx` / admin routes | mitigate | Guard redirects missing token to `/admin/login?next=<sanitized current admin path>`; backend APIs still enforce 401; client guard is UX, not sole authority (Task 3) |
| T-26-03 | Information Disclosure | `AdminLoginForm.tsx` | mitigate | JWT stored only in `sessionStorage` key `nqu_admin_token`; never placed in URL/query params; generic error message for auth failures (Task 2) |
| T-26-04 | Tampering | Login flow | accept | Backend already verifies Turnstile server-side with expected action and rate limiting; phase does not change backend contract (verified in `backend/app/api/v1/auth.py`) |
</threat_model>
