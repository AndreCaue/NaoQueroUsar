<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser location -> 401 redirect handler | Current path/search used to build return-to; must be sanitized before use in login redirect |
| Public privacy page -> admin login route | Public page exposes a discoverable link; route itself must remain protected by auth and not leak privileged data |
| Client sessionStorage -> admin extraction flow | Token removal on 401 prevents stale-session reuse in UI; backend remains authority |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-01 | Spoofing | 401 handlers in ReviewQueue/EditJobDialog/SocialPostsClient/ExtractForm | mitigate | All 401 redirects build target via `buildAdminLoginHref(window.location.pathname + window.location.search)` so return-to passes sanitizer from Plan 01 (Task 1, Task 2) |
| T-26-02 | Elevation of Privilege | `frontend/app/admin/paste/ExtractForm.tsx` | mitigate | Extraction UI requires `useAdminGuard()` token; unauthenticated users redirected by guard; 401 clears token and redirects to `/admin/login` (Task 1) |
| T-26-03 | Information Disclosure | `frontend/app/(public)/privacidade/page.tsx` | accept | Link discloses existence of admin login route only (low sensitivity, required by ADMN-02); no credentials, tokens, or admin data exposed (Task 3) |
| T-26-04 | Tampering | 401 redirect flow | mitigate | Token removed from sessionStorage before redirect on 401; hard navigation used to clear in-memory state (Task 1, Task 2) |
</threat_model>
