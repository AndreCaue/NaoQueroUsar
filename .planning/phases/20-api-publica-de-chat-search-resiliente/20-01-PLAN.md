<objective>
Implementar o contrato público do chat-search (`POST /api/v1/public/chat-search`) que combina a extração/mapeamento de intenção da Fase 19 com a busca determinística existente, retornando interpretação transparente + resultados pagináveis em `JobPublic` sem contatos, com proteções de abuso/custo/tempo e fallback controlado.

Purpose: Entregar o núcleo backend de API-01/API-02/API-03 para que o frontend público consuma busca por linguagem natural com segurança, resiliência e equivalência ao contrato público atual.
Output: Schemas/config/knobs do chat, seam de intent com timeout dedicado, endpoint público registrado e operacional no router v1.

### Decision coverage (CONTEXT.md)
- D-01: Endpoint público `POST /api/v1/public/chat-search` (JSON, sem auth) com `message` + paginação no body JSON.
- D-02: Envelope `interpretation` + `results` (`items` `JobPublic`, `page`, `limit`, `total`) sem contatos.
- D-03: Paginação `page>=1` default 1, `limit` 1–50 default 20; busca determinística equivalente a `GET /api/v1/public/jobs` / `list_published` para `applied_params` efetivos (`q`, `city`, `sort`) com mesmo `total`.
- D-04: Interpretação expõe contrato completo server-authoritative: `understood`, `field_statuses`, `applied_params`, `limitations`, `meta`.
- D-05: Rate limit dedicado por IP resolvido + endpoint (reuso `app.core.ratelimit`, `key_style="endpoint"`, 429 pt-BR + `Retry-After`).
- D-06: Limite curto/estrito de mensagem (obrigatória, trim, faixa segura) com 4xx pt-BR seguro.
- D-07: Timeout/orçamento curto dedicado para extração de intent do chat, desacoplado de `GROQ_TIMEOUT_SECONDS` admin.
- D-08: Erros seguros pt-BR: validação/tamanho 400/422, rate limit 429, falha LLM → 200 degradado, inesperado → 500 genérico com log server-side.
- D-09: Falha/timeout/indisponibilidade LLM → interpretação degradada sem resultados automáticos (`applied_params` nulos, `results` vazio `items=[] total=0`, page/limit preservados) com orientação para busca manual.
- D-10: Causa diferenciada via `meta`/`limitations` e `degradation_reason` (`llm_unavailable` | `timeout` | `no_extractable_params` | `empty_input`) com `field_statuses` coerentes.
- D-11: Orientação pt-BR explícita pronta para exibição em `meta.guidance` e/ou limitações, além de flags estruturadas.
- D-12: Resposta rápida com fallback controlado; sem retries longos fora do orçamento (tentativas adicionais só se couberem).
- D-13: Campos não nativos (salário, modalidade, tipo de contrato, senioridade): apenas aproximação via `q` mapeado + sinalização; sem pós-filtro estruturado nem afirmar filtragem inexistente.
- D-14: Aproximações/limites com aviso agregado claro em `limitations`/`meta.guidance` e `field_statuses`/motivos por campo.
- D-15: “Vagas parecidas” tratadas como aproximação textual limitada (termos em `q` quando possível), sem similaridade semântica/vetorial garantida.
- D-16: Cidades/locais fora da whitelist nunca inferidos para SP/RJ/BH; aplicar apenas partes seguras (ex.: `Remoto`), termos úteis em `q` quando apropriado e marcar restante ignorado/aproximado com motivo.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> POST /api/v1/public/chat-search | Entrada pública não confiável (mensagem NL, paginação) chega ao backend com acesso indireto a LLM e busca |
| backend chat-search -> Groq intent seam | Texto do usuário é dado não confiável enviado ao provedor LLM para extração de parâmetros |
| backend -> resposta pública JSON | Dados de busca/intent serializados ao cliente; contatos não podem vazar |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01 | Tampering / Elevation of Privilege | intent extraction (prompt/input) | mitigate | Reusar seam existente com delimitadores/sanitização (`intent.client`), nunca executar instruções do usuário; contrato final server-authoritative via `map_intent`/`extract_and_map_intent` (D-04) |
| T-20-02 | Denial of Service | `backend/app/api/v1/public.py` POST chat-search | mitigate | Rate limit dedicado por IP+endpoint (`limiter.limit(chat_search_limit)`), limite estrito de tamanho/trim da mensagem no schema, orçamento curto de timeout de intent e fallback rápido (D-05,D-06,D-07,D-12) |
| T-20-03 | Information Disclosure | resposta/erros do chat-search | mitigate | Retornar apenas `JobPublic` (sem `contact_email`/`contact_phone`) e envelope de interpretation; erros 4xx/5xx com `detail` pt-BR genérico/seguro e logs apenas server-side, sem stack/vazamento interno (D-02,D-08) |
| T-20-04 | Spoofing / Tampering | parâmetros aplicados na busca | mitigate | Ignorar parâmetros não autorizados do cliente para busca; usar somente `applied_params` finais (q/city/sort) do mapper determinístico em `list_published` (D-03,D-04,API-01) |
| T-20-05 | Denial of Service (cost/latency) | chamadas Groq no endpoint público | mitigate | Timeout dedicado curto (`CHAT_SEARCH_INTENT_TIMEOUT_SECONDS`), evitar retries longos fora do orçamento e degradar para 200 controlado com orientação em falha/timeout (D-07,D-09,D-12) |
</threat_model>
