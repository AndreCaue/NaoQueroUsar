# Phase 8 — Wave 3: Delete Action and End-to-End Flow Integration

## Objective

Implement the hard delete action for admin jobs and integrate the full end-to-end flow (paste → extract → review → approve). This wave delivers the delete capability and validates the complete workflow that the admin review area enables.

## Purpose

Wave 3 implements criteria 3 (hard delete, idempotent) and validates the E2E flow. The delete action is essential for admin to remove unwanted jobs, and the E2E flow integration ensures the entire pipeline from Phase 2 extraction works end-to-end within the admin review context.

**Key dependencies from Waves 1 and 2:**

- Frontend: Admin page with job list, approve and edit modals working, toast notifications configured
- E2E: The paste→extract→review pipeline from Phase 2 is theoretically connected

**Key decisions from CONTEXT.md:**
- D-E2E-05: Exclusão via `DELETE /admin/jobs/{job_id}` é **hard delete**. A operação é naturalmente idempotente: chamar delete duas vezes no mesmo job retorna 404 na segunda chamada (job já foi removido). Não há "soft delete" nem "archive" — o modelo Phase 1 não possui flag de soft delete.
- D-E2E-02: **Auto-dedução** — se o mesmo texto for colado duas vezes, o sistema suprime o duplicate e exibe notificação ao admin: "Essas vagas já foram inseridas". O hash do texto é usado para comparação (normalizado: lowercased, acentos removidos, espaços collapse). Rationale: reduz noise na fila; volume 100-500/month torna dedup viável; a revisão manual ainda captura casos edge.
- D-E2E-01: Quando `POST /admin/extract` retorna 0 linhas válidas (todas descartadas pelo LLM), a resposta é um `ExtractSummaryResponse` válido com `saved_pending=0, saved_needs_review=0, discarded=[...], alerts=[...]`. O frontend deve exibir "Nenhuma vaga encontrada no texto" como resultado bem-sucedido, não como erro.

**Contract defines:** Delete job function.

**Existing state:** May have other CRUD functions (create, get, approve, update); need to add delete_job.

**Required changes:**
1. Implement `delete_job(db: AsyncSession, job_id: str) -> dict`:
   ```python
   async def delete_job(db: AsyncSession, job_id: str) -> dict:
       """Hard delete de uma vaga. Operação idempotente: segunda chamada retorna 404 (job já removido).
       Não há soft delete nem archive — o modelo não possui flag de deleted."""
       job = await db.get(Job, job_id)
       if not job:
           # Já foi deletado; retorna 404 que o front trata como "já não existe" (idempotente)
           raise HTTPException(status_code=404, detail="Vaga não encontrada")
       await db.delete(job)
       await db.commit()
       return {"detail": "Vaga excluída"}
   ```
   - Key: if job not found (already deleted), raise 404 — this makes the operation idempotent per D-E2E-05
   - If job found, delete it and commit

### End-to-End Flow Integration

The E2E flow integration validates that the complete pipeline works:

1. **Paste**: Admin pastes raw text from groups into `POST /admin/extract` (Phase 2 endpoint)
2. **Extract**: Groq LLM extracts jobs, returns `ExtractSummaryResponse` with saved_pending, saved_needs_review, discarded, alerts
3. **Queue**: New pending jobs appear in `GET /admin/jobs?status=pending` (Wave 1 list)
4. **Review**: Admin views queue, sees text snippet preview (Wave 1 JobGrid)
5. **Approve**: Admin approves a job, status → published, expires_at refreshed (Wave 2)
6. **Delete**: Admin deletes a job, hard delete, idempotent (Wave 3)
7. **Deduplication**: If same text pasted twice, auto-deduplication suppresses duplicate with notification (D-E2E-02, integrated in extract endpoint from Phase 2)
