# Phase 8 — Wave 1: Admin Queue View and Protection

## Objective

Implement the admin job queue view with authentication protection and city filtering, so that an authenticated admin can see the pending job list with proper filtering and pagination. This delivers the foundational UI and backend endpoints for the review area.

## Purpose

This is the entry point for the admin review area (criteria 1 and 4 from success criteria). Without authenticated access and the ability to view the pending queue, no approve/edit/delete actions are possible. Wave 1 establishes the scaffolding that all subsequent waves build upon.

## Context

**Loaded artifacts:**
- `.planning/phases/08-admin-review-area-completeness/08-CONTEXT.md` — full phase decisions (D-01 through D-03, D-E2E-07, D-E2E-09)
- `.planning/phases/08-admin-review-area-completeness/08-RESEARCH.md` — research on admin patterns, Turnstile, JWT, city filters
- `.planning/ROADMAP.md` — Phase 8 depends on Phase 1 (auth), Phase 2 (extração), Phase 4 (tema)
- `.planning/STATE.md` — milestone v1.1 EmpregaNoix, Phase 7 complete, starting Phase 8

**Key decisions from CONTEXT.md:**
- D-01: Fila principal exibe apenas vagas `pending`; `needs_review` em aba separada
- D-02: Ordenação padrão: mais recentes primeiro (`created_at DESC`), tie-break por `id DESC`
- D-03: Filtro por cidade: chips SP, RJ, BH, Remoto; sem busca por texto livre
- D-E2E-07: Todas as rotas admin exigem `Authorization: Bearer <token>` via `require_admin`. Acesso sem token = 401.

## Interfaces

### Backend — `backend/app/api/v1/admin.py`

**Contract defines:** All admin routes under `/admin` prefix, all requiring `require_admin` dependency.

**Existing state (before this plan):** Router exists but routes are minimal; auth not yet enforced on all routes.

**Required changes:**
1. Add `require_admin` dependency to all admin routes:
   - `GET /admin/jobs` — list pending jobs with city filter and pagination
   - `POST /admin/jobs/{job_id}/approve` — approve job (pending → published)
   - `PUT /admin/jobs/{job_id}` — edit job (partial update, at_least_one_contact validation)
   - `DELETE /admin/jobs/{job_id}` — hard delete job
   - `GET /admin/extract` — extraction endpoint (already exists, but must also require admin)

2. Ensure `require_admin` from `app.deps` is imported and used in every route.

3. Add city filter query parameter to `GET /admin/jobs`.

4. Add pagination (offset-based) to `GET /admin/jobs`.

### Frontend — `frontend/app/admin/review/page.tsx`

**Contract defines:** Page at route `/admin/review` (or route group `(admin)`) displaying the pending job list.

**Existing state:** New file — admin review area not yet implemented.

**Required changes:**
1. Page component that fetches `listJobsByStatus({ status: 'pending', city? })` from `frontend/lib/api.ts`
2. City filter chips component (reusable pattern from Phase 4 public board)
3. JobGrid component displaying pending jobs with text snippet preview alongside fields
4. Pagination controls (reusable `Pagination.tsx` from `frontend/components/board/`)
5. State management for current city filter and page number

### Frontend — `frontend/components/admin/Toast.tsx`

**Contract defines:** Minimal toast component for admin feedback, no external dependencies.

**Existing state:** New component — toasts not yet implemented in admin area.

**Required changes:**
1. Functional component accepting `type` (success | error | info) and `message` (string) props
2. Fixed positioning, top-right alignment, auto-dismiss after 3 seconds
3. pt-BR messages mapped by type
4. No external libs (sonner, react-hot-toast) — inline CSS or minimal Tailwind v4 classes
5. Export `toast.success()`, `toast.error()`, `toast.info()` helper functions
