| Token | Value | Usage |

| sm | 8px | Compact gaps between controls (`gap-2`) |
| md | 16px | Default card/content padding (`p-4`), grid gaps (`gap-4`) |
| lg | 24px | Section/layout gaps (`gap-6`) |

| 3xl | 64px | Page-level spacing |

## Interaction Contracts

### 1) Active City Filter (CITY-01, D-01..D-04)

| State | Condition | UI | Behavior |
|-------|-----------|----|----------|
| Default | Board loaded, active cities available | Render `Todas` + only active city chips in `CITY_OPTIONS` order | Chips reflect published/active jobs in general board, not narrowed by current `q` (D-01) |
| No active jobs for a city | City has zero published/non-expired jobs | Chip omitted (D-02) | Do not render disabled placeholder chip |
| Selected city still active | `filters.city` is in `available_cities` | Selected chip uses active styling | Normal filter behavior; URL keeps `city` |
| Selected city obsolete | `filters.city` not in `available_cities` | No obsolete chip shown; `Todas` becomes active state after cleanup | Clear `city` from URL and show broad board state (D-03). Use `router.replace(..., { scroll: false })` or equivalent URL replacement; no dead empty screen caused by stale city. |
| Active cities payload | `GET /api/v1/public/jobs` response | Includes `available_cities` alongside `items/page/limit/total` (D-04) | Same response used by home board; no separate client-only source of truth. |

**Data contract (D-04, discretion resolved):**

| Field | Type | Semantics |
|-------|------|-----------|
| `available_cities` | `string[]` | Supported city slugs with at least one published, non-expired job in the general board. Values limited to known slugs (`sao-paulo`, `rio-de-janeiro`, `belo-horizonte`, `remoto`). Return in stable `CITY_OPTIONS` order. Empty array when no active cities. |

**Implementation note:** Backend may compute with a dedicated query over published/non-expired jobs (`status='published' AND expires_at > now()` semantics), independent of `q`/`city`/`sort` request filters. Do not expose contacts or add a new endpoint.

### 2) Sort Dropdown (UIUX-01, D-05..D-08, D-12)

Replace native `<select id="board-sort">` with a custom accessible dropdown.

| Part | Contract |
|------|----------|
| Trigger | Button-like control, `h-11`, `rounded-lg`, `border-line-strong`, `bg-canvas`, text `text-sm text-fg`, width compatible with current layout (`w-40` baseline, responsive-safe). Shows current label (`Mais recentes` / `Mais antigas`). |
| Trigger ARIA | Use button pattern with `aria-haspopup="listbox"` or `menu`-equivalent only if listbox semantics fully preserved; preferred: `button` + `aria-haspopup="listbox"` + `aria-expanded` + `aria-controls` pointing to listbox id. Visible/accessible name remains "Ordenar por". |
| Listbox panel | Opens below trigger, `bg-surface` or `bg-canvas` consistent with board, `border border-line`, `rounded-lg`, subtle shadow allowed if minimal; `z-index` above toolbar content. |
| Options | Two options: `recentes` => "Mais recentes", `antigas` => "Mais antigas". Each option has `role="option"` (or equivalent) and `aria-selected`/active indication. |
| Open/close | Click/tap trigger toggles. Close on option select, outside click, and `Escape` (D-06). Selecting commits sort via existing `commit({ sort })` and resets page as existing behavior does. |
| Keyboard | Trigger focusable. `Enter`/`Space` opens/selects as appropriate. `ArrowDown`/`ArrowUp` moves active option. `Escape` closes and returns focus to trigger. `Tab` follows normal flow after close/move as appropriate; no focus trap. |
| Active option | Visually marked (accent text/border/background subtle) and announced by ARIA selected state. |
| Hover/focus options | Consistent with city chips language: accent border/text and subtle accent-tinted background on hover/focus; smooth transition (D-08, D-12). |

**Trigger states (D-07):**

| State | Visual |
|-------|--------|
| Default | `border-line-strong`, `bg-canvas`, `text-fg` |
| Hover | Accent border/realce aligned with chips/inputs: `hover:border-accent` and/or `hover:text-accent-soft`; subtle background only if consistent and minimal |
| Focus-visible | Existing global focus ring: 2px `accent-soft`, offset 2px |
| Open/active | May keep accent border/text emphasis to indicate open state; do not use filled accent background |

**Option states (D-08):**

| State | Visual |
|-------|--------|
| Default | `text-fg`, transparent/subtle background |
| Hover | `bg-accent/10`-equivalent subtle tint (or existing token-compatible rgba), `text-accent-soft` or `text-fg` with accent border cue; keep readable |
| Keyboard focus/active descendant | Same visible treatment as hover/focus |
| Selected | Clear selected marker; may use semibold + accent-soft text and/or subtle accent background. Keep contrast on dark surface. |

### 3) City Chips Hover (UIUX-01, D-10, D-11, D-12)

| Chip State | Default | Hover | Focus-visible | Active/Pressed |
|------------|---------|-------|---------------|----------------|
| Inactive (`Todas` or city not selected) | `border-line-strong`, `text-fg`, transparent bg | Reinforced light hover: keep border/text accent cue + add subtle background tint, e.g. `hover:border-accent hover:text-accent-soft hover:bg-accent/10` (token-equivalent). Smooth transition. (D-11) | Global 2px `accent-soft` outline, offset 2px | Browser default; no layout shift |
| Active (selected) | `bg-accent-strong`, `text-white`, semibold | Light hover: slight darken/realce of accent fill, e.g. `hover:bg-accent-strong-hover` or equivalent subtle overlay; maintain white text legibility. (D-10) | Global focus-visible ring visible against accent fill | Browser default |

**Consistency rule (D-12):** Chips, sort trigger/options, and cards share the same accent language and transition timing. Intensity differs by component: chips light/reinforced-light, cards medium, sort options menu-item subtle.

### 4) Job Card Hover (UIUX-01, D-09, D-12)

| State | Visual | Behavior |
|-------|--------|----------|
| Default | Existing card: `bg-surface`, `border-line`, `rounded-[12px]` | Unchanged |
| Hover (pointer:fine) | Medium intensity: border becomes accent and add subtle background/surface lift cue. Recommended: `hover:border-accent hover:bg-[rgba(139,92,246,0.04)]` or equivalent subtle tint; optional very subtle shadow only if minimal and token-consistent. No large transform/scale. (D-09) | Smooth transition (`transition-colors`, optionally `transition-all` limited) |
| Focus-within | Keep existing `focus-within:border-accent` | Keyboard focus on internal buttons must preserve visible card focus cue |
| Reduced motion | Existing global reduced-motion rules apply | No animated hover motion; instant state change acceptable |

**Layout stability:** Hover/focus must not change card dimensions, padding, border width, or grid flow.

## Responsive / Accessibility Contract

- Mobile-first; preserve existing toolbar sticky behavior and horizontal chip scroll on small screens.
- All interactive controls keep minimum 44px touch target (`min-h-11`).
- Sort dropdown panel must remain usable on narrow screens (no horizontal overflow; width constrained to trigger/container).
- `focus-visible` uses existing global accent-soft outline; never remove outlines.
- Custom dropdown must be keyboard operable and screen-reader understandable (button/listbox semantics, `aria-expanded`, `aria-controls`, option selected state).
- `Escape` closes sort dropdown and returns focus to trigger.
- Outside click closes sort dropdown.
- Respect `prefers-reduced-motion: reduce` (already in `public.css`).
- Hover-only cues must not be the sole indicator of interactivity; controls remain visibly interactive by default.
