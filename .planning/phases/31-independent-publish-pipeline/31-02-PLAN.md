<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser admin UI → FastAPI admin endpoints | Authenticated admin boundary; requests must be authorized and validated. |
| Admin endpoints → publish pipeline/DB | Internal boundary; state transitions must be idempotent and provider-isolated. |
| Admin UI/log responses → operator | Output boundary; must not expose tokens/secrets/raw sensitive payloads. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-01 | Tampering | Approve/worker/retry endpoints | mitigate | Keep `require_admin`/`require_cron_secret`; provider-aware retry infers/validates post ownership and uses idempotent pipeline reconciliation before publish (D-17, PUBL-04). |
| T-31-02 | Information Disclosure | status/list/log endpoints and admin UI | mitigate | Return only safe fields (status, pt-BR error, IDs/permalink, attempts/timestamps, sanitized log summaries); never include access_token/raw Graph payloads (PUBL-03). |
| T-31-03 | Denial of Service | retry storms / duplicate dispatch | mitigate | Preserve idempotency/no-op outcomes; do not expose auto-retry for rate-limit/ambiguous blocked states; approve dispatch uses isolated per-provider try/except and single dispatch per due post (PUBL-01/PUBL-05). |
| T-31-04 | Elevation of Privilege | admin-only publish controls | mitigate | All new endpoints require `require_admin`; worker remains cron-secret protected; frontend uses Bearer token and 401 redirect pattern. |
| T-31-05 | Repudiation | audit history UI/API | mitigate | Add safe SocialPostLog read endpoint and render attempt history/timestamps/results in admin UI (PUBL-03). |
</threat_model>
