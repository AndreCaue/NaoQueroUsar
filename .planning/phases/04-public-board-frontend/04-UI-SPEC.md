# Phase 04 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Escopo da fase:** o board público (`/`), o modal de detalhe, a busca/filtro/ordenação com estado na URL, e o fluxo de reveal do contato consumindo o endpoint do Phase 03. **Não** inclui a área admin (Phase 5), badge/report (Phase 6) nem páginas legais (Phase 6) — os espaços para esses elementos são reservados, não implementados.

**Relação com o Phase 03:** este contrato **reutiliza os tokens do `03-UI-SPEC.md`** (`--bg`, `--panel`, `--accent`, `--accent-soft`, `--warn`, escala de 4px, 2 pesos, 4 tamanhos, focus ring `#a78bfa`). Duas coisas mudam, deliberadamente: (a) a stack de estilo do **board público** passa a Tailwind v4 (decisão travada no `PROJECT.md`, adiada no Phase 03) e (b) o preenchimento de CTA usa `#7c3aed` em vez de `#8b5cf6`, porque branco sobre `#8b5cf6` dá **4.23:1** e falha o critério WCAG AA do UIUX-01. O admin (`globals-admin.css`) **não é tocado**.

### shadcn gate (executado 2026-10-22)

`components.json` **não existe** e o projeto é Next/React → o gate foi acionado. Resultado: **shadcn não inicializado**. Motivos: (1) não há canal interativo nesta execução para escolher um preset; (2) a superfície do Phase 4 é **uma página + um dialog** — um sistema de componentes seria overhead contra o "board enxuto"; (3) todos os tokens visuais já estão travados e são reutilizados do Phase 03. **Ponto de override:** se o usuário quiser shadcn, ele precisa escolher o preset e rodar `npx shadcn init --preset …` antes do plan-phase; nada neste contrato depende de shadcn.

### Onde o Tailwind entra (e onde não entra)

- `frontend/app/(public)/public.css` → `@import "tailwindcss";` + bloco `@theme` + base do board. Importado **somente** por `app/(public)/layout.tsx` (CSS é route-scoped no App Router), então o Preflight **não** alcança `/admin/*`.
- `frontend/app/globals.css` → permanece mínimo (`:root { color-scheme: dark; }`, `body` background/color) e passa a ser importado pelo `app/layout.tsx` (hoje não é importado por ninguém — corrigir).
- `frontend/app/admin/paste/globals-admin.css` → **intocado**. O admin continua 100% plain CSS com os tokens dele.

```css
/* app/(public)/public.css */
@import "tailwindcss";

@theme {
  --color-canvas: #0f0a1a;      /* 60% — fundo da página */
  --color-surface: #1a1025;     /* 30% — cards, dialog */
  --color-line: #2a1f3d;        /* borda decorativa de card/dialog */
  --color-line-strong: #6d5a91; /* borda de CONTROLE (input, botão secundário, chip) — 3.26:1 */
  --color-fg: #e2e8f0;
  --color-fg-muted: #b8a9cc;
  --color-accent: #8b5cf6;      /* marca: bordas/hover/indicador */
  --color-accent-soft: #a78bfa; /* TEXTO de acento + focus ring */
  --color-accent-strong: #7c3aed;       /* preenchimento de CTA (branco 5.70:1) */
  --color-accent-strong-hover: #6d28d9;
  --color-donate: #facc15;
  --color-danger: #f87171;
  --color-danger-soft: #fecaca;
  --radius-card: 12px;
  --radius-dialog: 16px;
}
```

> **Regra dura:** `#8b5cf6` **nunca** carrega texto (branco sobre ele = 4.23:1, reprova AA). Preenchimento com texto = `#7c3aed` (5.70:1) ou `#6d28d9`.

## Spacing Scale

Mesma escala do Phase 03 (múltiplos de 4). Sem token novo.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap ícone↔texto, padding inline de chip, gap entre meta itens |
| sm | 8px | Gap entre chips, padding vertical de chip, gap título↔meta |
| md | 16px | Padding de card, gap entre linhas do formulário de busca |
| lg | 24px | Padding lateral de página no mobile, gutter do grid, seções do dialog |
| xl | 32px | Gap vertical entre toolbar e grid, padding do dialog no desktop |
| 2xl | 48px | Respiro entre blocos de página (header → toolbar) |
| 3xl | 64px | Altura do header, padding vertical do footer |

Exceptions:
- **Touch targets:** mínimo **44×44px** para todo elemento interativo (chips, "Ver a vaga", "Ver mais", X do dialog, paginação, "Doações"). A exceção ao 8-point vale só para `min-height`/`min-width`.
- **Input de busca:** altura **48px** (mobile-first, dedo).
- **CTA do reveal no dialog:** altura **48px**.
- **Turnstile:** o iframe da Cloudflare ocupa ~**300×65px** — reservar `min-width: 300px; max-width: 100%` e **nunca** aplicar `transform`/`scale` (regra herdada do Phase 03).
- **Slots de ADS:** alturas fixas de mídia (90px / 250px), não tokens de espaçamento — ver §ADS.
- **Container:** `max-width: 1120px`, gutter 24px (mobile 16px), sidebar de ADS 300px fixos.

## Contrato de dados (o que a UI pode renderizar)

| Campo (`JobPublic`) | Onde aparece | Regra |
|---------------------|--------------|-------|
| `id` | chave de lista, `key` do cache de contato, payload do reveal | nunca exibido |
| `title` | card (`Heading`) + dialog | obrigatório |
| `company` | card (linha 1) + dialog (subtítulo) | `null`/vazio → **linha omitida** (nunca "—") |
| `activities` | card (`line-clamp-3` + "Ver mais") + dialog (completo) | `null` → card pula o preview e o toggle; dialog pula a seção |
| `requirements` | **somente** dialog | seção omitida quando `null` |
| `salary` | card (meta) + dialog | texto livre — renderizar **cru** (`R$ 2.500`, `A combinar`), sem parse/formatar |
| `benefits` | **somente** dialog | seção omitida quando `null` |
| `city` | chip no card + seção `Local` no dialog | uma das 4 labels fixas |
| `status` | não renderizado (a lista só traz `published`) | — |
| `created_at` | `Publicada em dd/mm/aaaa` | `Intl.DateTimeFormat("pt-BR", { timeZone: "America/Sao_Paulo" })`, **data absoluta sempre** |
| `expires_at` | `Encerra em dd/mm/aaaa` (dialog) | mesma formatação |
| `contact_email` / `contact_phone` | **nunca** vêm da lista (PUBL-05) | só de `ContactRevealResponse`, via `POST …/reveal-contact` |

`ContactRevealResponse` → UI: `contact_phone` vira `https://wa.me/{somente dígitos}?text={encodeURIComponent(mensagem)}`; `contact_email` vira `mailto:{email}?subject={encodeURIComponent("Candidatura: " + title)}`. Sempre `target="_blank"` + `rel="noopener noreferrer"` no `wa.me`; `mailto` sem `target`.

**Datas são absolutas por decisão:** "há X dias" depende do relógio do cliente e causa divergência de hidratação entre RSC e browser. `dd/mm/aaaa` em `America/Sao_Paulo` é determinístico no servidor e atende o pt-BR.

## Contrato de URL e estado

O estado do board **mora na URL** (SRCH-01/02/03 + critério 3 do Phase 4). Nada em `localStorage`.

| Param | Valores | Default | Comportamento |
|-------|---------|---------|---------------|
| `q` | texto livre (1–80 chars) | ausente | Busca server-side; **sem acento e case-insensitive** (responsabilidade do backend, índice pg_trgm do Phase 1) |
| `city` | `sao-paulo` \| `rio-de-janeiro` \| `belo-horizonte` \| `remoto` | ausente = **Todas** | Slug na URL ↔ label acentuada na UI; o front envia o **slug** ao backend, que o traduz para o valor canônico sem acento (`Sao Paulo`) — ver D-06b |
| `sort` | `recentes` \| `antigas` | `recentes` | Omitido quando default. `recentes` → `created_at DESC`; `antigas` → `ASC` |
| `page` | inteiro ≥ 1 | `1` | Omitido quando `1`. Tamanho de página fixo: `limit=24` |

Regras:
- Mudança de `q`/`city`/`sort` **reseta `page`** (remove o param) e usa `router.replace(url, { scroll: false })` — não polui o histórico nem salta a tela.
- Digitação → **debounce de 300ms**; `Enter` faz flush imediato (cancela o timer e navega).
- Paginação usa `<Link>` (`push`) e rola para o topo da região de resultados.
- Slug/valor desconhecido → ignorado, cai no default (não 400, não crash).
- `q` é trimado; string vazia remove o param. Máx. 80 chars no input (`maxLength`).
- O backend **precisa** aceitar `q`, `city`, `sort` em `GET /api/v1/public/jobs` (hoje ele tem um comentário de fronteira "search/city/sort are Phase 4"). O planner deve incluir essa extensão no Phase 4, com os **mesmos nomes** (`q`, `city`, `sort`) — sem camada de tradução de nome.
- O modal **não** busca detalhe a partir da lista: o `JobPublic` da lista já tem tudo. **Exceção (D-10a):** quando `?vaga=<uuid>` aponta para uma vaga **fora do filtro atual**, o servidor resolve esse id via `GET /api/v1/public/jobs/{id}` (que é contact-free) para o deep-link funcionar. Nenhum `GET /jobs/{id}` no caminho normal de abrir um card.

## Interaction Contract

### A. Anatomia do card (PUBL-01/02)

```
┌──────────────────────────────────────────┐  bg #1a1025 · borda 1px #2a1f3d · radius 12 · padding 16
│ {company}                    14/400 muted│  (omitida se null)
│ {title}                      20/600 · 2 linhas
│ [📍 {city}]  Salário: {salary}           │  chip 14/400 + valor 14/600
│ {activities}                 16/400/1.5 · line-clamp-2 (<640) / line-clamp-3 (≥640)
│ Ver mais                     14/600 #a78bfa (só se len > 160)
│ Publicada em dd/mm/aaaa      14/400 muted
│ ┌──────────────────────────────────────┐ │
│ │             Ver a vaga               │ │  secundário · h44 · full-width
│ └──────────────────────────────────────┘ │
└──────────────────────────────────────────┘
```

- O card **não** é clicável como um todo (evita abertura acidental ao rolar). Dois alvos explícitos: `Ver a vaga` (abre o dialog) e `Ver mais` (expande `activities` **no lugar**, vira `Ver menos`, `aria-expanded`).
- `Ver mais` só existe quando `activities.length > 160`. Estado expandido é local do card e **reseta** em qualquer mudança de `q`/`city`/`sort`/`page` (o grid remonta).
- O `activities` expandido no card **não** substitui o dialog: o dialog traz `requirements`/`benefits`/datas.
- `<article>` por card; título do card é `<h2>`.
- Cards da mesma linha equalizam altura (grid `items-stretch`); o CTA fica ancorado no rodapé (`mt-auto`).

### B. Toolbar (busca + cidade + ordenação)

Ordem no DOM (e no mobile): `form[role="search"]` → grupo de chips → linha "contagem + ordenar".

1. **Busca**: input `type="text"`, `inputMode="search"`, `enterKeyHint="search"`, `autoComplete="off"`, `aria-label="Buscar vagas"`, altura 48px, ícone `search` 20px à esquerda (decorativo, `aria-hidden`), botão X 44×44 à direita quando `q !== ""` (limpa imediatamente, sem debounce).
2. **Chips de cidade**: **single-select** + `Todas`; `aria-pressed` por chip; container com `role="group"` e `aria-label="Filtrar por cidade"`; no mobile é uma **linha com scroll horizontal** (`overflow-x-auto`, `scrollbar-width: none`, bleed `-mx-4 px-4`), no ≥640 quebra em linha.
3. **Ordenar**: `<select>` nativo estilizado (bg `#0f0a1a`, borda `#6d5a91`, h44, chevron `aria-hidden`), `aria-label="Ordenar por"`, largura 160px. Nativo de propósito: teclado mobile e leitor de tela já corretos, zero JS.
4. **Contagem**: `aria-live="polite"`, atualizada a cada resposta.
5. **Sticky**: a toolbar fica `sticky top-16` com bg `#0f0a1a` e `border-b #2a1f3d`; `backdrop-filter` **não** é usado (custo em mobile antigo).

### E. Reveal do contato (PUBL-04, herda o contrato do Phase 03)

Máquina de estados: `idle → verifying → revealed | error(403|429|404|network|timeout)`.

| Estado | Visual |
|--------|--------|
| `idle` | Botão preenchido **`Mostrar contato`** (h48, full-width no footer). Widget Turnstile **não montado** (token vive 300s — não pré-mintar). Se o contato já está no cache de memória desta aba para este `job_id`, pula direto para `revealed` |
| `verifying` | Botão `disabled`, rótulo `Verificando...`; `<Turnstile>` montado **neste instante** com `action="reveal"`, `theme="dark"`, `appearance="interaction-only"`, `id="turnstile-reveal"` (≠ do `id` default do login, que coexiste no mesmo app), `key={revealKey}`; `onVerify` → `POST /reveal-contact` imediatamente |
| `revealed` | Footer substituído: valores crus (`#a78bfa`/600) + **`WhatsApp` preenchido** (primário) e **`Enviar e-mail` secundário**; em mobile empilhados (gap 8), em ≥640 lado a lado. Só renderiza o canal que existe |
| `error(403)` | Painel de erro com `body.detail` verbatim; `revealKey++` (remonta o widget — token consumido nunca é reenviado); botão vira `Tentar novamente` |
| `error(429)` | Painel de erro com `body.detail`; botão `disabled` com contador `Aguarde {n}s` (usa `Retry-After`; fallback 10s) |
| `error(404)` | Painel de erro `Vaga não encontrada ou expirada.`; botão vira `Fechar` |
| `error(network)` | Painel `Falha de conexão...`; `Tentar novamente` (com remount do widget) |
| `error(timeout 15s sem token)` | `Não foi possível concluir a verificação. Tente novamente.` + remount |

Regras duras:
- **Cache de contato (D-04):** o contato revelado fica em **memória** (um `Map<job_id, ContactRevealResponse>` em `useRef` no host do dialog) durante a vida da aba. Reabrir a mesma vaga **não** pede novo token. **Nunca** `sessionStorage`/`localStorage`/IndexedDB/cookie/URL. Um reload completo limpa tudo. Isso **substitui** a regra "never cache across modal open/close" do `03-UI-SPEC.md` §B — a decisão posterior D-04 (docstring de `ContactRevealResponse`) é a autoritativa.
- Um único widget de reveal por vez (só existe enquanto o dialog está aberto e em `verifying`).
- O front **não** valida `job_id` da resposta? Valida: se `response.job_id !== job.id`, descarta e mostra o erro de rede (proteção contra resposta trocada).
- Token nunca é reenviado: todo erro remonta o widget (`key` nova), padrão do Phase 03 (`next-turnstile@1.0.7` não tem `resetKey`).
- CTA do reveal é o **focal point** do dialog (único botão preenchido); o bloco de contato revelado é o payoff (`#a78bfa`/600).

### F. Header, footer e Doações (UIUX-02)

- Header `sticky top-0`, h64, `bg #0f0a1a`, `border-b 1px #2a1f3d`, container 1120px. Esquerda: wordmark `NaoQueroUsar` (Heading 20/600; "NaoQueroUsar" em `#e2e8f0` com ponto final `#a78bfa`). Direita: `Doações`.
- Slogan ao lado do wordmark só em ≥768 (Label muted); no mobile fica no footer.
- `Doações` é um `<a href="/doacoes">` (não um botão morto), h44, texto `#facc15`/14/600, borda `rgba(250,204,21,.40)`, fundo transparente, **efeito só no hover** (`bg rgba(250,204,21,.12)`, borda `#facc15`). Nada de animação, glow ou pulso.
- `/doacoes`: página estática mínima no mesmo shell (título + copy do contrato). O botão nunca aponta para `#`.
- Footer: borda superior `#2a1f3d`, `© 2026 NaoQueroUsar` + slogan (Label muted). **Espaço reservado** para os links legais do Phase 6 (não criar links mortos agora — TRST-03 é Phase 6).
- Skip link: primeiro focável, `sr-only` até receber foco, aponta para `#vagas`.

### G. Universal

- Focus ring `2px solid #a78bfa`, `outline-offset: 2px`, em **todo** focável (`:focus-visible`).
- `prefers-reduced-motion: reduce` → sem `animate-pulse`, sem `transition` de duração > 0, sem `scroll-behavior: smooth`.
- Nenhuma informação transmitida só por cor (chip selecionado = fill + peso 600 + `aria-pressed`; erro = ícone? não — texto + borda).
- Toque mín. 44×44 com ≥8px entre alvos adjacentes.
- Sem `transform`/`scale` no iframe do Turnstile.
- `lang="pt-BR"` no `<html>` (já existe) e `<meta name="theme-color" content="#0f0a1a">`.

## ADS (UIUX-03)

Espaços **reservados e visíveis**, nunca colapsados — a vaga de anúncio já existe no layout antes de haver anunciante (evita CLS no Phase 6).

| Slot | Onde | Dimensão | Visibilidade |
|------|------|----------|--------------|
| `ad-header` | Abaixo do header, acima do `<h1>` | 100% × **90px** (conteúdo máx. 728px centrado) | sempre |
| `ad-sidebar` | Coluna direita do layout | **300px × 250px**, `position: sticky; top: 96px` | só **≥1024px** (`hidden lg:block`) |
| `ad-inline` | Dentro do grid, `col-span-full` | 100% × **90px** | sempre; inserido **após cada 6 cards** (índices 6, 12, 18 da página de 24) |

Tratamento do placeholder: `border: 1px dashed #6d5a91`, `border-radius: 8px`, fundo transparente, texto centrado `Espaço publicitário` (Label 14/400, `#b8a9cc`), `aria-label="Espaço publicitário"`. O slot **mantém a altura** mesmo vazio. Não usar `aria-hidden` (é conteúdo informativo do layout, não decoração); quando um anúncio real entrar, o placeholder é substituído sem mudar a caixa.

Layout do board em ≥1024: `grid-template-columns: minmax(0,1fr) 300px; gap: 24px` — o slot inline vive **dentro** da coluna de conteúdo, não na sidebar.

## Responsive Contract

Breakpoints = defaults do Tailwind (não inventar novos).

| Faixa | Grid de cards | Sidebar ADS | Header | Toolbar | Dialog |

- O grid usa `gap: 24px` (16px no mobile), `align-items: stretch`.
- Textos longos quebram (`overflow-wrap: anywhere` em `title`/`activities`), nada de truncar por overflow do container.

### FLAGs de Dimension 2 (aceitos como recomendações de execução)

1. **Focal point do board não declarado.** O `<h1>` *Vagas abertas* + o input de busca são o ponto de entrada; o primeiro card ancora o grid e **todos** os `Ver a vaga` são `outline` para não competir com o CTA de busca.

### Ajustes de redação incorporados da verificação

- O reveal **não herda** o `appearance` do login: o login implantado usa `appearance="always"` (`ExtractForm.tsx:119`); o reveal declara `interaction-only` por conta própria. Sem colisão — ids distintos (`turnstile-widget` no login, `turnstile-reveal` no reveal).
- A tabela de copy é intenção de design, não literal para os erros de backend: o texto exibido é `body.detail` verbatim (o backend emite hífen, não travessão).
- O cache de contato por aba deve ser **module-scope/context**, não um `Map` em `useRef` do host do dialog — um `useRef` morre se o `JobGrid` desmontar (navegação client-side para `/doacoes` e volta).
