<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → reveal endpoint | Turnstile token + job id are untrusted; backend is the authority |
| API → browser | contact values cross the wire only after verification |
| URL → dialog | `?vaga=` is attacker-controllable |
| client memory | revealed contact must not persist beyond the tab |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-12 | Spoofing | Turnstile widget | mitigate | Mount only on click, `action="reveal"`, single widget per document, `key` bump after every error so a consumed token is never resent; backend enforces the action |
| T-04-13 | Information Disclosure | contact cache / DOM | mitigate | Module-scope `Map` only, cleared by reload; no storage/cookie/URL; grep gate rejects `localStorage`/`sessionStorage`/`indexedDB`; contact markup exists only in `revealed` |
| T-04-14 | Tampering | `wa.me`/`mailto` hrefs | mitigate | Phone reduced to digits, fixed `https://wa.me/` host, message/subject `encodeURIComponent`-encoded, CR/LF stripped from e-mail |
| T-04-15 | Information Disclosure | `?vaga=` enumeration | accept | IDs are opaque v4 UUIDs; expired/unknown ids return the same 404 and the same UI state; no extra data is exposed |
| T-04-16 | Denial of Service | reveal retries | mitigate | 429 cooldown from `Retry-After` (now readable via CORS), disabled button while counting; server limiter remains authoritative |
</threat_model>
