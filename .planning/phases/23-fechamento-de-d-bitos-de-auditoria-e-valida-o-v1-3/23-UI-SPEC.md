## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/text tight gaps, micro spacing (`gap-1`, `mt-1`) |
| sm | 8px | Compact element spacing, chip/list gaps (`gap-2`, `p-2`, `mt-2`) |
| md | 16px | Default element/container spacing (`p-4`, `gap-4`, `mt-4`) |
| lg | 24px | Section/dialog padding on larger viewports (`sm:p-6`, `py-6` contexts) |
| xl | 32px | Layout/page-level gaps where already established |
| 2xl | 48px | Major section breaks (if needed; preserve existing layout rhythm) |
| 3xl | 64px | Page-level spacing (if needed; preserve existing layout rhythm) |

Exceptions: `12px` (`p-3`, `gap-3`, `py-3`, `space-y-3`) is an established compact spacing step in chat/dialog UI and MUST remain allowed for touched components to avoid visual drift; 44px minimum touch target remains required for interactive controls (existing `h-11 min-h-11` / `min-height: 44px`), not as a layout spacing token.

## Interaction Contract (Phase 23 scope)

> Prescriptive behaviors required by locked decisions/research; no new features.

### D-14 — `frontend/lib/api.ts` (`chatSearch`)
- On HTTP 200, parse JSON defensively: `try { return parsed ChatSearchResponse } catch { throw new ApiError("Resposta inválida do servidor.", 0) }`.
- Transport/timeout failures remain typed, pt-BR, and contact/internal-detail safe (existing pattern). No raw exception text exposed to UI.

### D-14 — `frontend/lib/chatApply.ts` (`canApplyChatToBoard`)
- Do **not** enable apply for a city-only interpretation when `applied_params.city` is non-normalizable to a useful canonical board state (prevents misleading no-op apply). Gating must be based on a useful normalized board outcome (not merely non-empty raw city string).
- Preserve existing canonical rules and supported cases: `appliedParamsToBoardFilters`/board application keeps `page=1`, clears `vaga`, respects supported `q/city/sort` (`sao-paulo`, `rio-de-janeiro`, `belo-horizonte`, `remoto`, `sort=antigas`).
- Preserve degraded/disabled gating: if `meta.degraded === true` or `meta.degradation_reason === "chat_disabled"`, apply is disabled.

### D-14 — Chat/detail a11y & focus (feasible, focused)
- **`ChatPanel.tsx`:** dialog semantics remain (`role="dialog"`, `aria-modal="true"`, `aria-labelledby`), Escape closes, backdrop/close button operable. Apply feasible focus improvement (e.g. move initial focus into panel/title/close control on open) without broad refactor.
- **`ChatWidget.tsx` + correlates:** when opening job detail from chat, pass/retain a meaningful trigger so close restores focus appropriately (improve over current null-trigger path where feasible). Keep canonical detail open/close and `vaga` sync behavior.
- **`JobDetailDialog.tsx`:** preserve native `<dialog>` focus/ESC/backdrop behavior and scroll lock; only minimal, safe focus adjustments if needed (no regression to reveal/report flows).
- Any a11y/focus item not viable without scope/risk creep MUST be explicitly deferred in phase artifacts (per D-14) rather than partially/unsafely implemented.

### Non-regression / privacy
- Contacts never appear in chat payloads/UI; detail reveal remains the canonical gated flow.
- Public board manual search/list/detail remains usable if chat is degraded/disabled.
- No visual redesign: keep existing spacing rhythm, borders/radii, colors, and component structure except minimal changes required for the above behaviors.
