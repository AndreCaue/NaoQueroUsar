```ts
// POST /api/v1/admin/jobs/{id}/social-post/generate -> SocialPostDraftResponse
// PUT  /api/v1/admin/jobs/{id}/social-post          -> SocialPostDraftResponse
// GET  /api/v1/admin/jobs/{id}/social-post          -> SocialPostDraftResponse (or not-found handled)
// PATCH /api/v1/admin/jobs/{id}/approve             -> { job: JobAdmin, social: { status: 'registered'|'skipped'|'warning', code?: string|null, message?: string|null } }

type SocialPublishMode = 'publish_now' | 'schedule';
interface SocialPostDraftResponse {
  job_id: string;
  provider: 'facebook';
  status: 'draft'|'scheduled'|'publishing'|'published'|'failed'|'cancelled';
  text: string;
  publish_mode: SocialPublishMode | null;
  scheduled_at: string | null; // ISO
  origin: 'llm' | 'template_fallback' | null;
  saved: boolean;
  frozen: boolean; // status != draft
  warning: string | null; // fallback/info
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser/admin UI -> backend admin API | UI envia ações de draft/save/approve com token admin; deve tratar erros sem expor segredos |
| Renderização de preview/texto do post | Texto vindo do backend é exibido em preview/textarea; deve ser renderizado como texto (sem HTML) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-11 | Elevation of Privilege | chamadas de draft/approve no frontend | mitigate | Reutilizar token admin existente via helpers em `frontend/lib/api.ts` com `Authorization: Bearer ${token}`; manter `handleAuthError` (401) em fluxos de fila/ações conforme padrão. |
| T-16-12 | Information Disclosure | toasts/erros de UI | mitigate | Exibir mensagens seguras/acionáveis retornadas (ex.: SITE_PUBLIC_URL) e mensagens genéricas seguras em falhas; nunca exibir segredos/tokens. |
| T-16-13 | Tampering (UI integrity) | aprovação usando estado não salvo / edição de congelado | mitigate | Implementar indicador `Alterações não salvas`, carregar draft salvo, desabilitar controles quando `frozen` (D-08/D-12) e lembrar que approve usa último draft salvo; renderizar preview como texto (`whitespace-pre-wrap`, sem dangerouslySetInnerHTML). |
| T-16-14 | Spoofing/Confusion | feedback de aprovação | mitigate | Em approve, sempre comunicar site publicado primeiro e outcome social separado (registered/skipped/warning) para não confundir falha social com falha da vaga (D-09/D-11). |
</threat_model>
