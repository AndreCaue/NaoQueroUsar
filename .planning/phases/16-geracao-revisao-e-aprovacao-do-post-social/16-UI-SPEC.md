## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f0a1a` (`--color-canvas`) | Page/dialog base backgrounds, input backgrounds, preview canvas |
| Secondary (30%) | `#1a1025` (`--color-surface`) + `#2a1f3d` (`--color-line`) | Dialog surface, section panels/cards, borders/dividers |
| Accent (10%) | `#8b5cf6` (`--color-accent`) / `#a78bfa` (`--color-accent-soft`) / `#7c3aed` (`--color-accent-strong`) | Primary CTA buttons, focus rings, selected toggle state, active interactive affordances, links in preview |
| Destructive | `#f87171` (`--color-danger`) | Validation/action errors, destructive confirmations only |

Supporting neutrals (existing tokens): `--color-fg #e2e8f0`, `--color-fg-muted #b8a9cc`, `--color-line-strong #6d5a91`.

Accent reserved for: primary action buttons ("Gerar rascunho", "Regenerar com IA", "Salvar rascunho"), focus-visible outlines, selected state of "Publicar agora"/"Agendar" toggle, and the preview link affordance. Accent must **not** be used for all borders, all helper text, or status badges.

Status/indicator color mapping (non-accent, restrained):
- Success/info notices: subtle accent-tinted surface `rgba(139,92,246,0.12)` with `border-accent`/`text-fg` (existing info pattern).
- Warning/social-failure notice: `rgba(248,113,113,0.12)` surface with `border-danger`/`text-danger-soft` text (actionable but non-blocking for site publish per D-09/D-11).
- Origin/state chips ("Gerado por IA", "Template de fallback", "Rascunho salvo", "Agendado/registrado — texto bloqueado"): neutral bordered chips (`border-line`, `bg-canvas`, `text-fg-muted` or `text-fg`) — no extra semantic hues.

## Component & Interaction Contracts

### Placement (D-05)
- Add a `Post para Facebook` section inside `EditJobDialog.tsx` below job fields and above the dialog footer, separated by `border-t border-line` and `mt-6 pt-6` (24px rhythm).
- Section remains within the dialog scroll area; snippet panel behavior unchanged.

### States
| State | Required UI |
|-------|-------------|
| No draft (empty) | Empty state heading/body + `Gerar rascunho` button |
| Loading (generate/regenerate/save) | Disable triggering control, show loading label, preserve existing visible text/preview |
| Draft (editable) | Textarea, counter, origin indicator, mode toggle, schedule picker (if agendar), preview, `Salvar rascunho`, `Regenerar com IA` |
| Fallback applied | Warning/info notice (fallback copy) + draft editable |
| Missing/invalid public URL | Inline actionable error near generate controls; generate/regenerate disabled or fails with message; job save/approve remain available |
| Unsaved changes | `Alterações não salvas` indicator; approval path must use last saved draft (D-08) — show reminder: `Salve o rascunho para usar este texto na aprovação.` |
| Approved/registered scheduled (D-12) | Textarea/read-only preview state, controls disabled (generate/regenerate/save/mode/schedule), `Texto bloqueado após aprovação` indicator |

### Controls behavior
- **Textarea:** full-width, `min-h` sufficient for ~6-8 lines, 16px text, editable unless frozen. Value is draft text.
- **Counter:** right-aligned meta text under textarea, updates live; >700 uses warning color token treatment (`text-danger-soft` or equivalent muted warning) but remains non-blocking.
- **Regenerate (D-02):** requires confirmation dialog before overwrite when non-empty draft exists; confirm uses destructive styling.
- **Publish now / Agendar toggle (D-07):** segmented/two-button toggle, default `Publicar agora`; selecting `Agendar` reveals date + time inputs labeled with `America/Sao_Paulo`.
- **Date/time inputs:** native inputs acceptable (`type="date"`, `type="time"`) styled to admin tokens, `min-h-11`; required when `Agendar` selected.
- **Preview:** bordered panel (`bg-canvas`, `border-line`, rounded-lg) showing rendered post text and the resolved public link `{SITE_PUBLIC_URL}/?vaga=<job_id>` as visible/link text when available.
- **Save (D-08):** explicit action; persists draft text + mode + schedule choice to backend `social_post` draft (upsert semantics).

### Approval feedback (D-09/D-10/D-11)
- Approve action keeps optimistic/site-first semantics for the job list; on completion show toast that always states site outcome first, then social registration outcome/warning.
- Social-step failures must never present as "vaga não publicada" and must never block queue progression.

## Accessibility & Motion

- All interactive elements >= 44px height, visible focus using `:focus-visible` accent-soft outline (existing base).
- Dialog retains native `<dialog>` semantics/focus trap/ESC behavior; confirmation sub-dialog (regenerate) follows same pattern.
- Toggle and schedule inputs have programmatic labels; counter associated via helper text/`aria-describedby` where practical.
- Respect `prefers-reduced-motion: reduce` (admin base already enforces near-zero motion); no new decorative animations.
- Contrast: maintain existing fg/muted/danger-on-dark token pairings; do not introduce low-contrast placeholder-only meaning.
