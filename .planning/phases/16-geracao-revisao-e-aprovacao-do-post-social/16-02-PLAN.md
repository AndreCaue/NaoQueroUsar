<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Admin client -> admin API | Chamadas de draft/approve exigem admin autenticado; payloads (texto/schedule/modo) são validados |
| Admin API -> job publish path | Publicação da vaga no site é caminho crítico e deve permanecer isolada de falhas sociais |
| Admin API -> social persistence | Registro/transição de social_post deve preservar imutabilidade e não vazar segredos/erros sensíveis |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-06 | Elevation of Privilege | novos endpoints `/admin/jobs/{id}/social-post*` e approve | mitigate | Proteger todas as rotas novas/evoluídas com `Depends(require_admin)` (padrão existente em admin.py); validar UUID/path e ownership por job_id. |
| T-16-07 | Tampering / Integrity | approve flow (D-09/D-11) | mitigate | Executar `approve_job` + `commit` + `refresh` primeiro; registrar social em bloco separado try/except com persistência própria (ou tratamento isolado) sem rollback/desfazer vaga; retornar outcome `registered|skipped|warning`. |
| T-16-08 | Tampering | mutação de draft aprovado (D-12/POST-05) | mitigate | Rejeitar generate/save quando `social_post.status != draft` com HTTP 409 e detail `Texto aprovado e bloqueado para envio.`; approve registra texto `scheduled` imutável. |
| T-16-09 | Information Disclosure | respostas/erros de API | mitigate | Não retornar tokens/segredos/stack traces; mensagens pt-BR seguras e acionáveis (ex.: SITE_PUBLIC_URL ausente) via `HTTPException`. |
| T-16-10 | Tampering / Input Validation | schedule e payloads | mitigate | Validar `publish_mode` e exigência de `scheduled_date/time` para agendar; converter BRT->UTC com helpers validados; rejeitar datas/horas inválidas com 422 claro. |
</threat_model>
